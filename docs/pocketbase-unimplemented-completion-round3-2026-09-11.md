## 승인된 대응 의미와 한계

- **`@rowid`:** SQLite physical rowid 대응물이 없는 PostgreSQL에서 stable internal UUID order로 명시한다. `ctid`를 사용하지 않고 생성 순서나 PB numeric rowid와 동일하다고 표현하지 않는다. custom text ID의 lexical sort는 일반 `sort=id`가 담당하고 `@rowid`와 cursor tie-break는 internal UUID를 유지한다.
- **페이지 API:** PB 호환은 explicit `compat=pocketbase&page&perPage` adapter와 exact page envelope에서만 제공한다. 기존 native cursor query/list/iterate API를 page API로 바꾸지 않는다. total과 items는 같은 authorization/membership snapshot이고, `skipTotal`은 count를 실제 생략한다.
- **application topic:** raw UTF-8 topic은 collision-safe `@app/<base64url>` canonical namespace로 운반한다. PB legacy bare application topic과 wire 표기가 다른 승인 차이이며 raw topic 자체는 codec roundtrip으로 보존한다.
- **text ID:** external text ID가 public identity이고 durable alias가 authoritative internal UUID를 가리킨다. PostgreSQL FK, transaction, cursor authority는 internal UUID를 유지한다. native/default UUID collection 계약은 바뀌지 않는다.
- **ACME:** RFC8555/HTTP-01 흐름, certificate issuance/cache/renewal/redirect/shutdown은 실제 local test CA로 검증했다. 공개 domain, public CA, production DNS 환경 검증 범위는 아니다.
- **UI extension:** operator가 startup configuration으로 제공한 trusted `fs.FS`만 실행한다. browser가 임의 코드를 설치하거나 동적으로 권한을 얻는 표면은 제공하지 않는다.
- **schema authority:** schema plan/apply, operation receipt와 migration ledger의 authoritative state는 PostgreSQL transaction에 있다. HTTP는 해당 상태의 adapter다.
