**PgBase 구현 상태**는 코드에 그 사용자 목표를 수행하는 기능이 있는지(`구현`/`부분`/`미구현`/`비대상`)만 판정한다. PB route·JSON·SDK·수명주기의 차이는 이 축을 낮추지 않고 **PB 동등성**에만 기록한다. `구현`은 이번에 production runtime을 보장한다는 뜻이 아니다. 실행 증거가 부족하면 `검증` 열의 `S`/`미검증`으로 남긴다. `동등 근거 충분`은 작은 단위의 핵심 동작과 PgBase test를 대조한 경우만 쓰며, route·오류 JSON·SDK를 포함한 drop-in 호환 보증은 아니다.

## 검증 한계와 재현 가능한 후속 확인

이번 감사에서 양쪽 fixed source, route registration, field/model contracts, checked-in PgBase unit/integration/UI test를 읽고 `go test`의 이전 PR #36 표적 실행 기록을 참고했다. 이번 **감사 turn에서 새 제품 테스트·PocketBase test suite·전체 CI·배포는 실행하지 않았다**. PostgreSQL integration은 `PGBASE_TEST_ADMIN_URL` 또는 격리 DB가 필요한 경우 skip될 수 있으므로, 파일의 `*_integration_test.go` 존재를 runtime 통과로 환산하지 않았다. OAuth/S3/mail provider, Windows self-update, browser accessibility, 설치된 schema 40 환경도 미실행이다.

따라서 이 문서는 PB v0.40.3 source snapshot에 대한 기능/계약 ledger다. PB main 이후 변경, 실제 network protocol fuzzing, SDK 무수정 app 실행, production migration/restore 성공은 별도의 matrix 기반 실행으로만 `동등 근거 충분`으로 올릴 수 있다. SDK 행은 공식 별도 js-sdk v0.26.9 및 dart-sdk v0.23.3의 public 기능군 spot-check이며, 전체 method API 전수 비교나 PB v0.40.3과의 exact dependency pairing은 아니다.
