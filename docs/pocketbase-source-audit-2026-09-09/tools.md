# PocketBase tools source audit

Pinned upstream: PocketBase v0.40.3, commit `5684ee24f1e88f71a2ede73d20cf547fbd509e16`. PgBase comparison point: `35af64c`.

## Authentication provider toolkit

PocketBase supplies a registry of 32 OAuth/OIDC providers with a common configurable provider contract, PKCE flags, token exchange, provider-specific profile mapping, raw provider profiles, and access/refresh-token metadata ([auth.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/auth/auth.go#L1), [base_provider.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/auth/base_provider.go#L1)). Provider adapters differ materially in when they trust an email: many require an explicit verified flag, GitHub/Gitea/Bitbucket make a second request for a primary verified address, and Spotify/Strava deliberately expose none. OIDC optionally validates configured issuers and JWK signatures; Apple always validates its signed ID token. PgBase instead exposes a configurable standard HTTP OAuth adapter and persists provider identities per auth collection; it does not ship PocketBase's provider catalog. **Difference: partial; high UX/configuration importance.**

The shared PocketBase user-info and JWK fetch paths read response bodies without an explicit byte ceiling, while PgBase's OAuth adapter caps JSON responses and restricts endpoints/redirects for its local-development threat model. **Difference: PgBase is narrower and more bounded; medium operational importance.**

## Filesystem and object storage

PocketBase's portable blob layer offers local and S3 drivers, lexicographic paged listing, attributes and metadata, ranged `ReadSeekCloser` reads, streaming writes with MIME sniffing and optional MD5 verification, copy, prefix deletion, and hooks ([bucket.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/filesystem/blob/bucket.go#L1), [filesystem.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/filesystem/filesystem.go#L1)). Its HTTP serving delegates conditional and byte-range behavior to `http.ServeContent`, selects inline versus attachment by MIME type, and adds CSP and 30-day cache headers. PgBase has local and S3 object stores and a database-backed file lifecycle in [`internal/filestore`](../../internal/filestore), with download authorization and API handlers; its storage interface is intentionally smaller and does not expose PocketBase's general listing/copy/hooks facade. **Difference: partial; medium importance for extension authors.**

PocketBase accepts thumbnail specifications `0xH`, `Wx0`, `WxH`, `WxHt`, `WxHb`, and `WxHf`: proportional resize, center/top/bottom crop, or fit, retaining supported formats and converting WebP output to PNG ([filesystem.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/filesystem/filesystem.go#L316)). PgBase does implement thumbnails in [`internal/filestore/service.go`](../../internal/filestore/service.go): it proportionally downsizes images to a single configured maximum dimension and never enlarges them. It does not expose arbitrary request-time width/height crop, fit, top, or bottom modes. **Difference: both implemented, PocketBase has richer transformations; medium user-facing importance.**

## HTTP routing and request/response utilities

PocketBase layers grouped routes and priority-aware hook middleware on Go's `http.ServeMux`. It adds middleware inheritance and named exclusion, a catch-all API-error route, response status/write tracking, field-selected JSON responses, file serving, upload conversion, and JSON, XML, URL-encoded, or multipart binding. Request bodies are replayable: reads are copied in memory until 16 MiB and then spill to a temporary file that is removed on close ([router.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/router/router.go#L1), [event.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/router/event.go#L1), [rereadable_read_closer.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/router/rereadable_read_closer.go#L1)). PgBase keeps HTTP transport and domain services separate and does not expose a reusable router/binder toolkit. Its query and mail inputs enforce feature-specific limits instead. **Difference: architectural; medium importance for extension authors, low importance for API parity.**

PocketBase converts validation errors into stable public `{code,message,params}` trees while retaining raw internal data only on the server-side `ApiError`. Its form binder coerces canonical booleans and minimal decimal strings, accepts a special raw JSON payload, and fills supported primitive, pointer, slice, nested, embedded, and `encoding.TextUnmarshaler` fields ([error.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/router/error.go#L1), [unmarshal_request_data.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/router/unmarshal_request_data.go#L1)). PgBase also uses stable validation codes and suppresses driver/server details, but its decoders are typed per endpoint and schema rather than reflection-based ([`internal/query/types.go`](../../internal/query/types.go), [`internal/query/codec.go`](../../internal/query/codec.go)). **Difference: same public-error goal, different binding seam; low parity importance.**

## Search, sorting, and response projection

PocketBase's search toolkit parses an expressive SQLite filter language with field-to-field comparisons, eight equality/order/contains operators plus their any-match forms, null/empty normalization, relation multi-match subqueries, 16 time macros, `geoDistance`, and bounded `strftime`. Its default provider limits are 3,500 bytes and 200 expressions per filter, eight sort entries, and 1,000 rows per page; totals and results run concurrently unless `skipTotal` is set ([filter.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/search/filter.go#L1), [provider.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/search/provider.go#L1), [token_functions.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/search/token_functions.go#L1)). PgBase accepts a narrower field-to-literal grammar with six comparison operators, 4,096-byte/100-node filters, eight sort keys, schema-aware typed values, indexed-sort enforcement, and signed keyset cursors capped at 200 returned records ([`internal/query/filter.go`](../../internal/query/filter.go), [`internal/query/compiler.go`](../../internal/query/compiler.go), [`internal/query/order.go`](../../internal/query/order.go)). PgBase additionally supports policy-checked relation traversal, but does not provide PocketBase's contains operators, time macros/functions, random sort, offset page totals, or field-to-field public filters. **Difference: substantial API behavior; high compatibility importance.**

PocketBase's `fields` projection works after JSON conversion, supports nested paths, root/subtree wildcards, and value modifiers such as Unicode-aware excerpts stripped from HTML ([pick.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/picker/pick.go#L1), [excerpt_modifier.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/picker/excerpt_modifier.go#L1)). PgBase returns the schema-defined record shape plus requested relation expansions and has no equivalent arbitrary response projection/modifier layer. **Difference: missing in PgBase; medium API/response-size importance.**

## Realtime subscriptions

PocketBase's tools package supplies an in-memory broker of 40-character client IDs, per-client channels and context, prefix-addressable topics, normalized per-topic query/header options, chunked fan-out, and SSE message framing ([broker.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/subscriptions/broker.go#L1), [client.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/subscriptions/client.go#L1), [message.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/subscriptions/message.go#L1)). PgBase's realtime service is durable and database-backed: committed outbox events receive a serialized delivery sequence, leases retry with backoff, replay cursors expire explicitly, retention advances a floor, and every read reevaluates current collection policy ([`internal/realtime/service.go`](../../internal/realtime/service.go)). Its API is collection/cursor based rather than PocketBase's arbitrary topic broker. **Difference: PgBase is more durable and policy-centric but less general; high architectural importance.**

## Mail, logging, templates, and shared primitives

PocketBase mail supports named From/To/Cc/Bcc recipients, HTML and text alternatives, custom headers, regular and inline MIME-sniffed attachments, send interception hooks, local `sendmail`, SMTP PLAIN or LOGIN authentication, implicit TLS, and synthesized Message-ID headers ([mailer.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/mailer/mailer.go#L1), [smtp.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/mailer/smtp.go#L1)). PgBase's mail seam deliberately sends one bounded plain-text message to one recipient, enforces a 64 KiB body ceiling and deadlines, requires STARTTLS or implicit TLS outside loopback development, and rejects CR/LF header injection ([`internal/mailer/mailer.go`](../../internal/mailer/mailer.go), [`internal/mailer/smtp.go`](../../internal/mailer/smtp.go)). **Difference: PgBase is narrower and more bounded; medium product importance if rich mail is desired.**

PocketBase also exposes a batch `slog.Handler` with structured validation-error normalization and manual/threshold flush; a concurrent generic map with atomic get-or-set and bounded insertion; cached `html/template` registries with an explicit raw-HTML function; quote/parenthesis-aware tokenization; panic-recovering goroutine helpers; casing/list/OS helpers; AES-256-GCM, hashes, HMAC, PKCE, HS256 JWT, and regex/random generators; and SQL/JSON-safe UTC date, geo-point, JSON array/map/raw wrappers ([batch_handler.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/logger/batch_handler.go#L1), [store.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/store/store.go#L1), [registry.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/template/registry.go#L1), [tokenizer.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/tokenizer/tokenizer.go#L1), [datetime.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/tools/types/datetime.go#L1)). PgBase generally uses standard-library or domain-local equivalents instead of maintaining a public utility surface. **Difference: mostly extension ergonomics; low core-product importance.**

## Audit status

`tools-ledger.json` is the raw per-file ledger. `tools-extra-ledger.json` is an intentional override for its 16 overlapping archive/cron/dbutils paths; the effective view is [tools-effective-ledger.json](tools-effective-ledger.json). Authentication; filesystem; hooks; inflection and list helpers; logging and mail; OS helpers; response picking; routing; routines; search; security; stores; subscriptions; templates; tokenization; and shared types are fully read. Archive, cron, and database-query helpers are also complete in [tools-extra-ledger.json](tools-extra-ledger.json). The effective merged scope is 185 read / 0 indexed; raw indexed values remain visible with override provenance in the effective ledger. see [tools-extra.md](tools-extra.md) for the calendar scheduling and PostgreSQL comparison.
