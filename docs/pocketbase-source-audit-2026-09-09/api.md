# PocketBase API, forms, and mail source audit

This audit compares PocketBase v0.40.3 at commit `5684ee24f1e88f71a2ede73d20cf547fbd509e16` with PgBase commit `35af64c`. The assigned 90 text files under `apis/`, `forms/`, and `mails/` were read, including their tests. The percentage estimate that preceded this audit was not used as a target.

## Findings

| Area | PocketBase source behavior | PgBase evidence | Result | Importance |
|---|---|---|---|---|
| Record CRUD and rules | Collection-scoped list/view/create/update/delete routes apply API rules, field hiding, relation expansion, multipart file extraction, request hooks, and auth-record management exceptions ([record_crud.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/record_crud.go#L31-L118), [record_crud_test.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/record_crud_test.go#L21-L120)). | PgBase declares separate admin, user, service, and anonymous record surfaces and enforces typed rules in its query/record-operation kernel ([router.go](/Users/yakisoba0728/Documents/GitHub/PgBase/internal/api/router.go:105)). File operations are separate. | **Partial / different** | High: the core data API exists, but hook behavior, dynamic response shaping, and multipart-on-record semantics are not PocketBase-compatible. |
| Atomic batch | `POST /api/batch` accepts JSON or multipart, permits record create/update/delete and PUT upsert, shares the outer auth context, ignores nested authorization headers, executes one transaction, rolls back on any nested failure or timeout, and returns each nested status/body ([batch.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/batch.go#L65-L170), [batch_test.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/batch_test.go#L176-L310)). | PgBase has collection record batch routes with bounded JSON operations, explicit idempotency and conditional-write behavior, but no generic internal-request envelope, PUT upsert, or multipart file multiplexing. | **Partial / different** | High for PocketBase client compatibility; PgBase exposes a narrower operation contract with explicit bounds. |

| Realtime | PocketBase uses SSE connect plus a subscription mutation request, authorizes each topic, enriches records, hides protected fields, and unsets client auth when auth records or collection secrets change ([realtime.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/realtime.go#L31-L175), [realtime_test.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/realtime_test.go#L25-L150)). | PgBase provides cursor-backed SSE delivery with scoped routes and durable decimal-string delivery identifiers. | **Partial / different** | High: both deliver events, but subscription lifecycle, replay model, payload enrichment, and SDK behavior differ. |
| Files | PocketBase issues short-lived file tokens and serves protected/original/thumb files through collection rules; thumbnails are generated concurrently with locking ([file.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/file.go#L24-L151), [file_test.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/file_test.go#L19-L120)). | PgBase has bounded file upload/download APIs, ownership/rule checks, scoped file tokens, and single-max-dimension proportional thumbnail generation; PocketBase additionally exposes request-selectable WxH crop/fit/top/bottom modes and uses a different file-token URL contract. | **Partial** | Medium. |

| Settings diagnostics | PocketBase settings APIs redact secrets on read, merge updates, and include live S3/email tests plus Apple client-secret generation ([settings.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/settings.go#L17-L145), [test_email_send.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/forms/test_email_send.go#L18-L118)). | PgBase configuration is environment/startup driven; local SMTP delivery exists, but there is no comparable settings CRUD or connection-test HTTP surface. | **Absent** | Medium for self-service administration. |
| Mail templates | PocketBase resolves collection-specific subject/HTML templates inside a shared layout for auth alerts, OTP, reset, verification, and email change ([record.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/mails/record.go#L20-L303), [layout.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/mails/templates/layout.go#L1)). | PgBase sends purpose-bound action links through a configured sender/SMTP adapter, with fixed local templates rather than collection-editable templates. | **Partial** | Medium for branding and per-realm UX. |
| Middleware contract | PocketBase's router order is activity logging, panic recovery, rate limiting, token loading, superuser IP filtering, security headers, then body limits; CORS, gzip, guest/auth/owner/same-collection guards are reusable middleware ([base.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/base.go#L31-L73), [middlewares.go](https://github.com/pocketbase/pocketbase/blob/5684ee24f1e88f71a2ede73d20cf547fbd509e16/apis/middlewares.go#L25-L180)). | PgBase centrally declares route admission, response caps, request byte limits, deadlines, CORS/CSRF, and redacted route-template logging ([router.go](/Users/yakisoba0728/Documents/GitHub/PgBase/internal/api/router.go:50), [middleware_test.go](/Users/yakisoba0728/Documents/GitHub/PgBase/internal/api/middleware_test.go:15)). | **Different, comparable coverage** | High: compatibility differs; PgBase defines explicit per-route bounds. |

## Scope conclusion

PgBase covers the main record, schema, authentication, files, and realtime axes, but the wire contracts and administration surface are not PocketBase-compatible. The largest functional omissions are the embedded operational APIs (backup, logs, cron, settings diagnostics, arbitrary SQL), PocketBase's generic multipart batch contract, OTP/impersonation/refresh auth semantics, PocketBase-compatible multi-mode image thumbnail transforms, broader request/model hooks, and editable mail templates. A single completion percentage would hide these product-boundary differences; capability-by-capability status is the defensible result.

The comparison concerns local source behavior only. External cloud operation, production SLOs, public publishing, and live third-party provider verification remain unverified.
