## Adopted design

The schema `FieldOptions` interface gains these portable members:

- `autogeneratePattern` (`AutogeneratePattern string`): text fields only. On
  create, the server generates a cryptographically random matching string only
  when the logical field key is absent. Any explicitly supplied value,
  including `""` or `null`, takes precedence and follows the ordinary text
  contract. Updates never generate. A text default and an autogenerate pattern
  cannot be combined. The pattern uses a bounded, generatable Go RE2 subset;
  unsupported or unbounded expressions and patterns whose maximum output can
  exceed the existing text byte budget are rejected at schema preview. Each
  candidate must also satisfy `minLength`, `maxLength`, `pattern`, format,
  domain, and allowed-value constraints.
- `deniedDomains` (`DeniedDomains []string`): text fields with `format=email`
  or `format=url` only. `allowedDomains` remains the allow list. Schema input
  canonicalizes both lists by trimming surrounding whitespace and trailing
  dots, lowercasing ASCII domain names, sorting, and rejecting empty, duplicate,
  malformed, or overlong entries. A host matches an entry exactly or as a
  subdomain. Both lists may be set; deny wins, then a nonempty allow list must
  match. Tightening either list runs the existing row preflight.

Autogenerated unique values use bounded retries. A candidate-specific
transaction advisory lock plus an existence check closes the concurrent-create
race before insert; invalid candidates and occupied values are regenerated up
to a fixed limit, then the write fails with a field-scoped
`autogenerate_exhausted` validation error. Ordinary explicit unique conflicts
retain the existing conflict contract. The idempotency request hash excludes
generated output, and replay lookup occurs before generation, so retrying a
committed create with the same key returns the original value. A failed or
rolled-back standalone or batch attempt leaves no generated record/artifact.

The query field modifier adopted in N4 is `:lower` for text/editor fields.
It is accepted on the terminal field of root and bounded relation filters and
compiles to PostgreSQL `lower(...)`; literals remain bound parameters. It is
also accepted in typed record-rule fields, including create/update/read/batch
authorization paths. It does not change sorting or stored values. Hidden-field
checks, relation depth/join budgets, filter byte/node budgets, and cursor query
fingerprints continue to apply and include the modifier.

GeoPoint traversal remains deliberately limited to the defined numeric
coordinates `field.lon` and `field.lat`. N4 adds the same coordinate paths to
typed record rules and verifies root and bounded relation record queries. It
does not expose arbitrary JSON properties, coordinate aliases, multi-relation
sorting, or deeper paths; existing relation depth, join, index, and root-row
budgets remain unchanged.

Other PocketBase write modifiers are classified but not adopted: numeric
`field+`/`field-` would conflict with PgBase's exact bigint/numeric transport
and optimistic-update contract; select/relation append/prepend/remove would
change duplicate/order and target-authorization contracts; file removal uses
PgBase's attachment lifecycle. Text `:autogenerate` is also not exposed as a
write-key modifier: N4's create-only absent-key rule gives explicit values one
unambiguous precedence contract. These remain documented differences rather
than silently accepted keys.

All new options flow through catalog responses, schema preview/apply, stable-ID
rename, `pgbase.schema/v1` import/export, administrator field editing, and the
TypeScript SDK. No parallel serializer is introduced; N1 can preserve the
options by using the canonical schema structures/export surface.

## Limitations and deliberate boundaries

- The generator accepts only the documented bounded generatable RE2 subset;
  anchors and other zero-width assertions, plus expressions that cannot be
  generated within a proven output bound, are rejected at schema preview.
- Domain values are ASCII DNS names. Internationalized domains must be supplied
  in their punycode form.
- `:lower` is filter/rule-only and text/editor-only. It does not alter sorting or
  stored values. GeoPoint traversal remains only `.lon` and `.lat`.
- PB numeric/select/relation/file write modifiers and text-key
  `:autogenerate` remain deferred for the contract reasons documented above.
- No migration files changed; N4 uses the existing `options_json` storage.
