# N7 — Dart SDK execution design

Baseline: `edf55690599fc63966d3e99996f9954649961074`, 2026-09-10.  This is a
**plan-only** commit.  It neither adds a Dart package nor changes the Go API.
The same Sol/Terra worker may begin implementation only after G0: N1–N5 are
remotely merged, CI is green, the live install is accepted, and Rawls has
announced the handoff.  Astra coordinates; it does not implement this stream.

## Outcome and compatibility boundary

N7 adds a maintained Dart/Flutter client for PgBase's existing HTTP contract.
It is not a PocketBase-Dart-SDK compatibility claim and does not add or alter a
server route.  The source of truth is the actual route registry/OpenAPI snapshot
plus the existing TypeScript SDK's user-facing behavior:

- `docs/openapi.routes.json` selects the admitted routes and access model.
- `sdk/typescript/src/index.ts` supplies the public user/auth, record, file,
  batch, ETag/idempotency, cancellation and realtime behavior.
- `sdk/typescript/src/admin.ts` supplies the separate cookie/CSRF administrator
  behavior.  A public bearer token is never sent through this client.
- `internal/api/record_handlers.go`, `batch_handlers.go`, `file_handlers.go`,
  `realtime.go`, and `errors.go` remain the HTTP wire authority.  Do not copy a
  handler's private Go data shape into the Dart package.

The public package is `sdk/dart`, package name `pgbase`, versioned locally until
release policy says otherwise, and has `publish_to: none`.  It must be useful
through a path dependency, but no `dart pub publish` is authorized.

## Package shape and ownership

The implementation owns only this new subtree and its tests/examples:

```
sdk/dart/
  pubspec.yaml                 # pgbase; publish_to: none
  lib/pgbase.dart              # deliberately small public exports
  lib/src/client.dart           # request construction, base URI, response/error mapping
  lib/src/transport.dart        # injected package:http Client and Abortable requests
  lib/src/auth.dart             # AuthStore, opt-in persistence, auth/realm flows
  lib/src/records.dart          # CRUD, cursor query, ETag/idempotency and batch
  lib/src/files.dart            # multipart, SHA-256 headers, download-token URL
  lib/src/realtime.dart         # SSE framing, resume, reconnect and de-duplication
  lib/src/admin.dart            # distinct administrator cookie/CSRF client
  lib/src/types.dart            # UUID, ExactDecimal, records/pages/results and DTOs
  lib/src/exact_json.dart       # lossless JSON parser/encoder and JSONB value model
  lib/src/errors.dart           # PgBaseError, admin error, cancellation and MFA error
  test/                         # deterministic unit + mock-wire tests
  test/live/                    # actual PgBase conformance, launched by a Go harness
  example/dart_cli/             # a path-dependent command-line consumer
  example/flutter_app/          # a path-dependent Flutter consumer and widget test
```

`sdk/typescript` stays untouched.  N7 may add a shared test fixture only when
both language SDKs consume it; otherwise Dart-specific fixture data stays under
`sdk/dart/test`.  Server routes, OpenAPI generation, authentication semantics,
and the administrator UI belong to their existing owners.  A discovered wire
defect is reported to Rawls with a minimal reproduction; it is not silently
patched from the SDK branch.

## Concrete public contract

`PgBaseClient(Uri baseUri, {http.Client? httpClient, AuthStore? auth})` is the
user client.  It owns no global client, accepts an injected `package:http`
client for testability, and exposes `close()` only when it created that client.
Requests use the current `AuthStore` token as `Authorization: Bearer ...`.
`PgBaseAdminClient` is a separately constructed client: it accepts a caller
provided cookie-capable transport, retains CSRF only in memory, and sends
`X-PgBase-CSRF` only for authenticated non-GET administrator mutations.  It
never consults `AuthStore`.

`AuthStore` starts in memory.  Persistence is opt-in through an asynchronous
`AuthStorage` interface (`read`, `write`, `clear`); Flutter secure storage is
an application choice, not a forced SDK dependency.  `restore()` is explicit.
Every token save/clear increments a generation.  Login/OTP/MFA/OAuth completion
only saves a token if its captured generation is still current.  Logout,
password change, and email-change confirmation clear the local token in
`finally`; realtime subscriptions observe the generation and stop immediately.
The server remains the authority for revocation and expiry, so a 401 does not
invent a refresh-token flow.

The user API covers the current TypeScript contract: root and named-realm
register/login/session/logout; reset, verification, email-change, OTP, MFA,
TOTP and OAuth flows; realm profile read/update; record list/get/create/update/
delete; cursor iteration; batch and multipart batch; file list/upload/delete/
token/download URL; and record SSE events.  `Records.create` requires the
caller-supplied idempotency key, `update`/`remove` require a strong ETag, and
the `WithETag` variants return both record and response ETag.  No automatic
retry is added for a mutation: callers retry an ambiguous create with the exact
same key and exact body.

The administrator API implements the currently exported TypeScript admin
operations under the same split: auth/session, catalog/schema plan/apply/
operation/export/import, logs, jobs, file and backup storage settings and
migrations, user/session administration, realtime status/retry, and system
status.  Plans retain the exact preview body and one generated operation UUID /
idempotency key for a lost-response replay.  It does not turn admin cookies
into user bearer credentials or promise cross-origin browser administration.

All non-2xx responses decode the existing `{error:{code,details}}` envelope
into `PgBaseError(status, code, details, etag)`.  An unreadable success JSON is
an error, never an empty successful object.  `RequestAbortedException` becomes
the SDK cancellation exception without rewriting it as a server error.

## Exact values and HTTP rules

The SDK cannot use an untyped `jsonDecode`/`Map<String, dynamic>` path for
record or error bodies.  N7 supplies a small lossless JSON AST and encoder:
objects reject duplicate keys, arrays preserve order, strings validate UTF-8,
and a JSON number retains its original lexical spelling.  Generic JSONB values
and raw response bodies use this AST.  Convenience DTO decoding is performed
only after the expected fields are selected from it.

PgBase record-field rules remain explicit: `integer` is a JSON integer;
`bigint` and `numeric` are decimal JSON strings; UUIDs are canonical UUID
strings; timestamps are RFC 3339 strings.  `ExactDecimal` preserves validated
decimal text and never accepts `double`; `PgBaseUuid` validates and normalizes
the canonical textual UUID.  The SDK does not infer a numeric field type from
an arbitrary record map or round a JSONB number.  SSE delivery IDs are decimal
strings validated with `BigInt` against signed int64, even on Dart platforms
where an `int` is arbitrary precision.

The HTTP adapter owns these invariants:

| Operation | Required wire behavior |
| --- | --- |
| JSON request | UTF-8 lossless encoder; `Accept: application/json`; JSON content type only when appropriate |
| Authenticated user request | current bearer token; URL path segments and query values encoded independently |
| Create | one `Idempotency-Key`; exact input bytes stay bound to an ambiguous retry |
| Update/delete | caller's strong `If-Match`; preserve failure ETag on a 412 |
| Batch | current user batch route, JSON and multipart `requests` envelope; file names/parts cannot overwrite the `requests` part |
| File upload | streamed multipart part plus `X-PgBase-File-Size` and SHA-256 calculated without a second whole-file copy |
| Cancellation | `http.AbortableRequest`, `AbortableMultipartRequest`, or `AbortableStreamedRequest` with one cancellation trigger per request |
| SSE | `Accept: text/event-stream`, optional `Last-Event-ID`, RFC framing including comments/multiline data, no browser `EventSource` dependency |

`package:http` 1.6.0 is the transport dependency because its supported
multi-platform client exposes abortable request types, streaming response
bodies, multipart requests, and injectable clients.  Direct dependencies are
`http: ^1.6.0` and `crypto` for SHA-256; development dependencies are `test`
and `lints`.  Do not add an auth-storage, cookie-jar, decimal, UUID, SSE, or
lossless-JSON package in the first implementation.  The package supplies the
small abstractions it needs so mobile secure storage and an administrator
cookie policy remain application-controlled.

For SSE, save every valid frame ID including `cursor` frames; reconnect with
that value after transport EOF/failure using 250 ms exponential backoff capped
at 10 s and a default maximum of five reconnects.  Suppress a delivery ID not
strictly after the saved cursor, de-duplicate at most 1,000 event UUIDs, and
surface HTTP 410 as an expired replay cursor so consumers reload records before
starting fresh.  A user logout, changed token, or cancellation stops both the
stream subscription and pending reconnect delay.

## Implementation sequence after G0

1. Create the package metadata, public barrel, analyzer/lint policy, local
   `PUB_CACHE`, and the injected abortable transport.  Freeze the public type
   names in a compile-only API test before adding endpoints.
2. Implement exact JSON, UUID/decimal validation, structured errors and request
   construction.  Port the TypeScript mock-wire cases for headers, status,
   error details, exact numeric strings, cancellation and malformed JSON.
3. Add `AuthStore`, root/realm auth flows and record CRUD/query/ETag/
   idempotency.  Include generation races: logout while login completes and
   token replacement while an old OTP/MFA completion returns.
4. Add batch, streamed file upload and download-token URL.  Test a lost create
   response replay, stale ETag, multipart request/file binding, cancellation,
   SHA-256/size headers, and zero-copy stream error cleanup.
5. Add SSE parser/reconnect and administrator client.  Test partial frames,
   comments, CRLF, multiline data, duplicate replay, large delivery IDs, 410,
   auth-generation shutdown and bounded reconnect exhaustion.
6. Add the Dart CLI and Flutter examples as independent path consumers.  They
   demonstrate login, exact numeric display, CRUD conflict handling, a file
   upload, and reconnecting record events; neither stores a token by default.
7. Run real PgBase conformance, static checks and the local consumer check.
   Request an independent standards/spec review before N7 is offered to Rawls
   for integration.

## Tests and required environment

Unit tests use `package:http/testing.dart` or a local scripted `BaseClient` so
they assert paths, headers and raw bytes without a network dependency.  The
live suite is a tagged Go harness that starts the repository's disposable
PgBase/PostgreSQL fixture, gives `sdk/dart/test/live` only its base URL and
ephemeral test principal, then executes the Dart tests.  It must cover real
authentication/revocation, CRUD/query cursor, 412 current ETag, idempotent
replay, JSONB/exact numeric round trips, batch/file transaction behavior, SSE
reconnect/410, and a representative administrator cookie/CSRF flow.  It never
uses a developer's existing database or token.

`HOME` and `PUB_CACHE` under that `.runtime` directory, then run `dart pub
get`, `dart analyze`, and `dart test`.  Dart 3.13.3 has no `dart pub pack`
subcommand.  Because `publish_to: none` deliberately blocks every publish
command, its pack-equivalent acceptance is a disposable path-dependent CLI
consumer that runs `pub get` and `dart run`; it must import only the public
package export.  Flutter is a hard environment prerequisite for the
Flutter-example widget test.  Install a matching Flutter SDK task-locally at
G0 and run `flutter test` there; do not turn its absence into a skipped N7
acceptance test.

## Preconditions and blockers

1. **G0 is not yet satisfied.** N1–N5 merge/CI/live-install acceptance and
   Rawls' handoff are required before any product/package files are created.
2. **N0 HTTP stability must be confirmed at G0.** Re-read the generated route
   snapshot and TypeScript contracts before writing endpoints.  Any route,
   envelope, strong-ETag, exact-JSON, or revocable-session change is a server
   contract change and needs Rawls' owner decision.
3. **Administrator transport support needs one explicit implementation choice:**
   the initial native and same-origin-web cookie transport must be selected and
   tested without making cross-origin browser admin a claim.  The public admin
   method set remains the existing TypeScript set.
4. **Public publishing remains blocked.** `publish_to: none`, local path
   consumer, and `publish --dry-run` are the approved boundary until a user
   separately authorizes pub.dev publication.
