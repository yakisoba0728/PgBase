## 기능 경계와 공개 설정

SQL console은 옵션이 없으면 route와 UI entry를 등록하지 않는 disabled 기능이다. 기능을
켜도 요청의 기본 mode는 `read`다. `write`는 다음 두 조건이 모두 충족되어야 한다.

1. 서버 옵션에 compiler/read/writer 전용 DSN과 extension table/column allowlist가 있다.
2. 요청이 `mode: "write"`를 명시하고, dry-run 여부와 각 statement의 bound parameter를
   함께 보낸다.

DB credential은 server-side option에만 존재하며 status, OpenAPI example, UI bootstrap,
error, log에 들어가지 않는다. N8 소유 public option 파일은
`pgbase/sql_console_options.go`로 두고 `SQLConsoleOptions`에 enablement, 세 역할 DSN,
write target, 기본/최대 timeout만 표현한다. 동시성·queue·SQL/result hard cap은 제품
상수라 운영자가 넓힐 수 없게 한다. 공용 [`pgbase/options.go`](../../../pgbase/options.go)에
`SQLConsole *SQLConsoleOptions` 필드를 추가하고 app lifecycle에 연결하는 일은 통합
lead 소유 변경으로 요청한다.

확장 write target은 `schema.table`과 허용 column 집합을 명시한다. schema wildcard,
database-wide write, `app.*`, table 이름만으로 허용하는 설정은 없다. startup 때 target의
OID와 shape를 검증하고, 실행 때 relation lock 후 다시 확인한다. 안전성을 입증하지 못한
target 하나라도 있으면 SQL console 전체 startup을 fail closed한다.

관리 collection read는 public row-rule 조회와 다른 관리자 기능이지만 무제한 table read가
아니다. catalog에서 허용 collection/field를 만들고 password field, auth secret, token/hash,
system control/ledger column을 제외한다. catalog/manifest와 catalog에 없는 `app` object는
허용 대상으로 추정하지 않는다.

## HTTP와 service 계약

예정 route는 다음 네 개다.

| Method/path | Access | 계약 |
| --- | --- | --- |
| `POST /api/admin/sql/queries` | `accessAdminSession` | bound statement array를 검증하고 실행을 생성한다. UI는 미리 만든 random UUID를 `PgBase-Operation-ID`로 보내며, 없으면 server가 만든다. write에는 `Idempotency-Key`가 필수다. |
| `GET /api/admin/sql/queries/{id}` | `accessAdminSameOriginRead` | 같은 admin session의 in-memory 상태/결과를 반환한다. 재시작·TTL 만료 뒤에는 같은 actor의 durable redacted 상태/receipt만 반환한다. |
| `POST /api/admin/sql/queries/{id}/cancel` | `accessAdminSession` | 같은 session 소유 pending/running 실행만 취소한다. backend PID를 입력으로 받지 않는다. |
| `GET /api/admin/sql/queries` | `accessAdminSameOriginRead` | 현재 actor의 bounded, cursor 기반 durable redacted history를 반환한다. raw SQL/params/result는 없다. |

service의 작은 표면은 아래 역할만 맡는다. API의 `AdminPrincipal`이나 `http` type을
`internal/sqlconsole`로 가져오지 않는다.

```go
type Service interface {
	Submit(context.Context, Actor, Request) (Execution, error)
	Get(context.Context, Actor, uuid.UUID) (Execution, error)
	Cancel(context.Context, Actor, uuid.UUID) (Execution, error)
	List(context.Context, Actor, Cursor) (Page, error)
	Close(context.Context) error
}
```

`Actor`는 administrator UUID와 process-local session key만 가진다. `Request`는 mode,
dry-run, timeout, 최대 10개의 `{sql, params}`를 가진다. 모든 SQL text 합은 UTF-8
64 KiB 이하이고 각 element는 정확히 한 statement여야 한다. result/log DTO는 service가
소유하고 API handler는 wire mapping과 `pgconn.PgError`의 허용된 위치/SQLSTATE mapping만
담당한다.

POST는 idempotency identity와 canonical request digest를 실행 전에 고정한다. 같은 실행
ID와 같은 digest는 현재 상태/receipt를 반환하고 다른 body는 conflict다. write receipt
보존 기간이 끝난 뒤에는 같은 mutation을 자동 재실행하지 않고 명시적인 expired/unknown
결과를 준다. read에도 execution ID는 있지만 transport가 자동 query replay하지 않는다.

## AST와 dependency guard

정규식, 첫 keyword, PostgreSQL read-only transaction, DB grant 어느 하나만으로 허용 여부를
결정하지 않는다. 검사 순서는 byte/statement count → AST syntax allowlist → relation/column
resolution → expression OID dependency → role privilege/target shape → 실행 직전 lock/revalidation
이다.

read grammar는 `SELECT`/`VALUES`, read-only CTE, join, subquery, group/order/limit의 명시
subset이다. write grammar는 allowlisted base table의 `INSERT`/`UPDATE`/`DELETE`와
`RETURNING`이다. 모든 node를 재귀 방문하고 방문하지 않은/새 node type은 거절한다.
다음은 항상 거절한다.

- SQL string 안 다중 statement, DML CTE, `SELECT INTO`, `CALL`, `DO`, `COPY`, DDL,
  `SET`, `SHOW`를 통한 secret/config 탐색, 직접 transaction control과 advisory lock
- schema/table/column wildcard write, system/temp relation, sequence/identity 또는
  `nextval`, large object, foreign table, partitioned/inherited table
- 임의 function/cast/operator/aggregate/window, 사용자 정의 type input/output 함수,
  system/secret function, volatile 또는 외부 효과를 가진 식
- RLS/policy, 사용자 trigger/rule, unsafe default/generated 식, allowlist 밖 object로
  이어지는 FK action/cascade를 가진 write target

read expression은 정확한 builtin function/operator/cast/aggregate/window OID allowlist를
통과해야 한다. view를 허용한다면 `pg_depend`를 따라 base relation과 식 의존을 끝까지
검사한다. compile에 temp view가 필요할 때만 compiler role의 전용 transaction/savepoint를
사용하고 모든 반환 경로에서 temp object를 제거한다. write 분석을 temp view 생성으로
대체하지 않는다.

parser 후보 판단은 다음과 같다.

| 후보 | 확인 결과 | 결정 |
| --- | --- | --- |
| [`pganalyze/pg_query_go/v6`](https://github.com/pganalyze/pg_query_go) 6.2.2 | PostgreSQL source parser를 쓰지만 cgo extension이다. 현재 [`scripts/build-local-artifacts.sh`](../../../scripts/build-local-artifacts.sh)의 3 OS × 2 arch `CGO_ENABLED=0` 계약과 충돌한다. | 직접 의존은 제외한다. |
| [`wasilibs/go-pgquery`](https://github.com/wasilibs/go-pgquery) `318158a2ab6787a92a4624ab23f3401a04ee6525` | libpg_query를 wazero로 실행해 실제 PostgreSQL AST를 pure-Go process에서 제공한다. release tag가 없고 wazero/WASM binary와 transitive dependency 비용이 있다. | 보안상 우선 후보다. 통합 lead가 exact pseudo-version을 승인한 뒤 six-build, binary delta, startup/parse memory, hostile corpus, license gate를 먼저 통과해야 한다. 지금 dependency를 추가하지 않는다. |
| [`zkrebbekx/pgparse`](https://github.com/zkrebbekx/pgparse) v1.3.0 | runtime dependency 없는 hand-written DML subset parser다. 실제 PostgreSQL parser와 dialect equivalence를 자동으로 얻지 못한다. | fallback 후보다. 선택 grammar 전체와 PG17/18 differential/adversarial corpus에서 fail-closed임을 입증할 때만 채택한다. |

실행 implementation이 parser AST를 그대로 신뢰하지 않도록 N8 자체 normalized statement/
expression model을 둔다. parser adapter는 unknown node를 오류로 바꾸고 source position을
보존한다. 실제 실행은 각 array element를 개별 PostgreSQL extended-protocol request로
보내고 server가 transaction을 소유한다. simple protocol과 client SQL 보간은 사용하지
않는다. pgx에서는 schema race에 named prepared statement/cache를 남기지 않는
`QueryExecModeDescribeExec`부터 검증한다.

## PostgreSQL 역할과 pool guard

역할은 모두 non-superuser, `NOINHERIT`, `NOCREATEDB`, `NOCREATEROLE`,
`NOREPLICATION`, `NOBYPASSRLS`이며 다른 role membership과 `SET ROLE` 경로가 없어야
한다. database/schema/table/function/type ownership을 갖지 않고 fixed
`search_path=pg_catalog`, UTC, bounded statement timeout을 쓴다.

- **compiler role**: 허용 relation SELECT와 분석용 TEMP만 가진다. persistent CREATE와
  write는 없다. AST syntax precheck 뒤에만 temp view를 만들 수 있다.
- **read role**: 허용된 safe relation/column SELECT만 가진다. TEMP가 없고 모든 실행
  transaction은 `READ ONLY`다.
- **writer role**: operator allowlist의 extension table/column DML과 runner의 고정 receipt
  SQL만 가진다. TEMP, managed schema grant, persistent CREATE, arbitrary function EXECUTE는
  없다.

PostgreSQL의 database `CONNECT`/`TEMP` 및 function `EXECUTE`에 대한 `PUBLIC` 기본 권한
때문에 role 자체 grant만 검사해서는 부족하다. startup guard는 effective privilege,
membership, ownership, schema create/temp, selected function/type execution을 catalog에서
검사하고 fail closed한다. 정확 builtin OID allowlist는 `PUBLIC EXECUTE`가 있어도 다른
함수를 허용하지 않는다. [PostgreSQL privilege defaults](https://www.postgresql.org/docs/current/ddl-priv.html)

통합 lead에 요청할 공용 DB seam은 대략 다음 모양이다. TLS/backup gate/session 기본을
복제하지 않으면서 N8이 raw `pgxpool.Config` callback을 소유하지 않게 하는 것이 목적이다.

```go
type RestrictedPoolOptions struct {
	ApplicationName  string
	StatementTimeout time.Duration
	LockTimeout      time.Duration
	TransactionMode  RestrictedTransactionMode
	CancelAndDiscard bool
}

func OpenRestricted(ctx context.Context, dsn string, options RestrictedPoolOptions, allowInsecure ...bool) (*RestrictedPool, error)
```

실제 이름은 통합 lead가 기존 database module 어휘에 맞춘다. pool은 connection 생성 때
fixed session policy를 적용하고, startup assertion query를 실행할 좁은 query seam과
`Acquire`/discard lifecycle을 제공해야 한다. N8 옵션은 raw callbacks를 받지 않는다.

## 실행, 취소, 원자성

global running 4, session running 2, pending 16을 hard cap으로 둔다. queue admission은
250 ms 안에 성공하지 않으면 시작되지 않는다. durable pending log를 기록하지 못하면
DB 작업을 전혀 시작하지 않는다. shutdown은 새 admission을 막고 pending을 canceled로,
running을 cancel/rollback 대상으로 만든 뒤 bounded drain하고 전용 pool을 닫는다.

상태는 `pending`, `running`, `succeeded`, `failed`, `canceled`, `timed_out`, `unknown`이다.
재시작 시 durable `pending`/`running`은 commit phase/receipt를 확인해 `succeeded` 또는
`unknown`으로 화해할 수 있는 write를 제외하고 abandoned failure로 종결한다. mutation을
자동 재실행하지 않는다.

- read는 server-owned `READ ONLY` transaction에서 실행하고 성공해도 항상 rollback한다.
- write는 모든 statement/target/dependency를 먼저 검증하고 relation OID 순서로 lock한 뒤
  catalog shape를 재검증한다. 최대 10개 statement를 같은 transaction에서 차례로 실행하고
  결과/affected cap까지 확인한 다음 receipt를 넣고 한 번만 commit한다.
- dry-run, 두 번째 이후 statement 오류, timeout, cancel, result/affected cap 초과는 전체
  rollback한다. serialization/deadlock도 자동 retry하지 않는다.
- 결과는 최대 1,000행, 128열, encoded cell 합 4 MiB, write affected rows 합 1,000이다.
  1,001번째 행/129번째 열/4 MiB 초과를 발견하면 write commit 전에 rollback한다.

running execution object만 빌린 connection과 cancel capability를 가진다. pending cancel은
queue에서 제거한다. running cancel은 해당 execution의 connection에만 PostgreSQL
CancelRequest를 보내고 확인되지 않은 cancel이 다음 query를 때리는 일을 막기 위해 그
connection을 pool에 반환하지 않고 폐기한다. client가 backend PID/secret을 주거나 다른
session의 PID를 cancel할 수 없다. PostgreSQL cancel은 전달/처리를 보장하지 않으므로
최종 상태는 rollback/receipt 확인 뒤 정한다. [PostgreSQL cancel request](https://www.postgresql.org/docs/current/protocol-flow.html#PROTOCOL-FLOW-CANCELING-REQUESTS)

commit이 시작된 뒤 cancel은 transaction이 끝났다고 추정하지 않는다. commit 응답이
유실되면 새 control connection으로 execution ID/request digest receipt를 조회한다. receipt가
있으면 `succeeded`/`committed: true`, bounded 확인으로 결론을 못 내리면 `unknown`이다.
이미 commit된 transaction을 canceled/rolled back으로 표시하지 않는다.

## durable log와 migration 예약

N8에는 새 system migration 하나가 필요하다. 번호는 **아직 41로 예약하지 않았으며** G3
green 뒤 통합 lead가 설치된 최신 번호 다음을 배정해야 한다. 원안은 두 relation이다.

- `pgbase_meta.sql_console_executions`: execution ID, administrator actor UUID, mode/dry-run,
  request fingerprint/idempotency digest, 상태, 생성/시작/종료/만료 시각, statement/row/byte
  count, SQLSTATE, committed/unknown summary. raw SQL, params, result, raw session은 없다.
- `pgbase_meta.sql_console_write_receipts`: execution ID와 request digest, commit marker,
  bounded 비민감 row/affected/byte summary. writer transaction 안에서 runner의 fixed SQL로
  기록하고 user statement에서는 접근할 수 없다.

in-memory result TTL은 terminal 뒤 5분이다. history 보존/삭제 정책은 migration 구현 전에
통합 lead가 기존 operation retention과 맞춰 고정한다. history API는 actor owner만 볼 수
있고 page serialization도 256 KiB 같은 별도 hard cap을 둔다. query text fingerprint와
canonical request digest는 기존 `TokenSecret`에서 각각 domain-separated key를 만들어
HMAC하고 raw SQL을 hashing input으로만 잠깐 사용한다.
application/request log와 metrics label에도 query, param, execution ID를 넣지 않는다.

## result wire와 UI

result는 arbitrary JSON value의 배열로 보내지 않는다. column은 name, PostgreSQL type
OID/name을 갖고 cell은 null/string/boolean/integer/decimal/json/bytes/temporal 같은 tag와
exact text를 갖는다. numeric/integer는 JSON number로 바꾸지 않는다. JSON/JSONB는 DB가
돌려준 canonical UTF-8 text를 tagged cell에 두고 UI가 기존 `parseJSON`으로 lossless
탐색하며 복사는 exact text를 쓴다. `null`은 빈 문자열과 별도 tag다. unsupported type이나
oversized cell은 query 실행 전/stream scan 중 fail closed한다.

terminal reply는 statement별 columns/rows 또는 command summary와 전체 elapsed, rows,
bytes, truncated, dry-run, committed 상태를 가진다. DB 오류는 statement index, safe message,
SQLSTATE, parser/`pgconn.PgError.Position` 기반 UTF-8 source position을 반환한다. durable
history에는 message/position을 보관하지 않는다.

N8 소유 UI 파일은 `ui/admin/src/pages/sql-console*`와 전용
`ui/admin/src/backend/sql-console-backend.ts`다. `/admin/sql` 페이지는 read가 기본이고,
write transaction을 명시적으로 선택할 때 allowlisted target/column과 dry-run을 보여준다.
execute/cancel, pending/running/final polling, statement별 result tab, bounded table 탐색/복사,
exact numeric/JSONB, error position, elapsed/rows/bytes/truncated/commit/unknown을 표시한다.
화면 이동이나 browser request abort만으로 server execution이 취소됐다고 표시하지 않고
명시 cancel 후 GET으로 최종 상태를 확인한다.

공용 [`ui/admin/src/routing/admin-location.ts`](../../../ui/admin/src/routing/admin-location.ts),
[`ui/admin/src/app.tsx`](../../../ui/admin/src/app.tsx), nav, backend session primitive 변경은
통합 lead가 N8 commit과 함께 적용한다. UI result unit test는 unsafe bigint/decimal,
JSONB nested number/null/duplicate-key failure, copy text, TTL/unknown/cancel state를 검증한다.

## G3 green 이후 구현 순서

1. 통합 lead가 fixed G3 base, system migration 번호, parser dependency 결정, 공용 DB pool/API
   composition/UI route 소유자를 확정한다.
2. `internal/sqlconsole`의 request/result/state model, AST adapter와 fail-closed grammar corpus를
   만든다. parser dependency gate와 six-build를 먼저 통과시킨다.
3. catalog/manifest read guard, extension target dependency inspector, compiler/read/writer role
   startup guard를 구현하고 isolated PG17/18에서 privilege bypass corpus를 통과시킨다.
4. scheduler, execution lifecycle, per-session ownership, result encoder와 cancel/discard를
   구현한다. read rollback과 Close/timeout/lock/contention/no-leak을 검증한다.
5. 배정된 migration에 durable execution log/receipt를 추가하고 write multi-statement,
   dry-run, failure rollback, cap rollback, lost commit response/replay/unknown을 검증한다.
6. N8 HTTP handler/route를 추가하고 auth/origin/CSRF, request/response/deadline/cardinality,
   다른 session 접근 거절, generated OpenAPI를 검증한다.
7. 전용 UI adapter/page를 연결해 실제 browser에서 long query cancel→다음 query 성공,
   error position 수정, exact copy, extension multi-DML commit/error/dry-run rollback,
   commit receipt를 재현한다.
8. 독립 Standards/Spec review를 고정 base와 candidate SHA로 요청하고, 통합 lead의 전체
   cross-feature/G5 gate에 stable commits만 전달한다.

예정 N8 소유 파일은 `internal/sqlconsole/`, `internal/api/sql_console*.go`,
`pgbase/sql_console*.go`, `ui/admin/src/pages/sql-console*`, 전용 UI backend adapter,
N8 test/fixture와 이 문서다. migration file/version registry, `go.mod`/`go.sum`, API
`Dependencies`/router caps, app options/composition/lifecycle, OpenAPI/generated artifacts,
UI routing/nav는 통합 lead와 충돌 가능성이 있는 공용 파일이다.

## G3 이후 fixture와 완료 증거

N8 전용 Docker project와 loopback ports는 통합 보드에 예약된 뒤에만 사용한다. 설치된
PG17 `55440`, HTTP `8090`, MinIO `59000`, N6/N7 fixture와 native/user data는 사용하지
않는다. fixture에는 최소 다음 역할/객체가 필요하다.

- control owner와 별도 compiler/read/writer login role, 잘못된 superuser/membership/
  TEMP/CREATE/PUBLIC function 권한 변형
- safe managed collection read와 password/secret/control column, 확장 namespace의 ordinary
  base table, trigger/rule/RLS/FK cascade/generated/default/identity/partition/view/foreign table
  우회 fixture
- `pg_sleep`/lock contention, cancel delivery race, connection drop before/after commit,
  server Close, result/affected 1,001행·129열·4 MiB 경계
- extension 여러 DML 성공, 두 번째 statement 실패, dry-run, timeout/cancel 전체 rollback,
  same-key replay와 different-body conflict, receipt retention 뒤 no replay
- 전후 catalog version, managed row revision, audit/outbox, schema ledger snapshot equality

| 인수 | 완료 증거 |
| --- | --- |
| N8.1 | AST 정상/우회 corpus, bound params, max 10 statement, read grammar와 extension `INSERT`/`UPDATE`/`DELETE RETURNING`, managed write 및 transitive side-effect 거절, multi-DML commit/전체 rollback |
| N8.2 | disabled/read-default/write-double-opt-in, 세 DB role startup guard, admin origin/session/CSRF와 cross-session 거절, 2/session·4/global·16 pending·250 ms, timeout/lock/size/result/affected caps와 connection 회수 |
| N8.2-log | durable redacted success/reject/cancel/timeout/restart/unknown history, start-log failure no execution, 5분 result expiry, owner 조회, same-transaction receipt와 retention 뒤 no mutation replay |
| N8.3 | 실제 admin browser에서 실행/취소/오류 위치/다음 query, exact bigint/decimal/JSONB 탐색·복사, write target 표시, multi-statement success/failure/dry-run/unknown final state |
| N8.4 | read always rollback, write one commit, failure/lock/timeout/disconnect/Close rollback, lost commit response reconciliation, no backend-ID cross-cancel, no idle tx/temp/connection leak, managed schema/record/audit/outbox 불변식 보존 |

완료는 기존 SQL View editor와 독립된 engine/page/API로 위 증거를 모두 갖춘 상태다. 직접
SQL이 PgBase record revision, authorization, audit, outbox를 재현하려 하지 않으며, 그
불변식을 우회할 수 있는 managed raw write를 차단하고 extension-owned table write만 별도
transaction/receipt 계약으로 제공한다.

## 통합 lead에 필요한 결정과 blocker

G3 구현 배정 전에 다음을 중앙에서 확정해야 한다.

1. N8 fixed base가 G3 core-green commit인지와 N8/N9의 새 worktree 기준 SHA.
2. system migration 번호 하나와 durable history retention. migration 1–40은 수정하지 않는다.
3. `go-pgquery` exact commit 채택 여부와 `go.mod`/`go.sum` 소유. 채택 전 six-build,
   artifact/memory/hostile corpus gate를 요구한다.
4. secure restricted pool constructor와 cancel-and-discard lifecycle의 공용 database API.
5. `pgbase.Options`/app construct·close, API `Dependencies`/route cap/deadline/response cap,
   OpenAPI/generated artifact, UI route/nav/session transport 공용 patch 소유자.
6. N6 user migration fixture가 만들 extension namespace/table/column 한 세트와 N7와 분리된
   N8 admin browser fixture. N6 public Go/JS API나 N7 SDK change는 N8 선행조건이 아니다.

현재 blocker는 제품 설계 불명확성이 아니라 G3 core-green 신호, migration 번호, parser
dependency와 위 공용 seam의 소유 결정이다. 이 문서 커밋 뒤에는 제품 구현을 시작하지 않고
통합 lead의 G3 배정을 기다린다.

## 확인한 primary reference

- PostgreSQL의 read-only transaction은 DML/DDL 일부를 막지만 모든 함수·sequence·외부
  효과에 대한 SQL sandbox가 아니다: [SET TRANSACTION](https://www.postgresql.org/docs/current/sql-set-transaction.html)
- extended query protocol은 Parse에 한 statement만 허용하고 bound parameter를 분리한다:
  [libpq command execution](https://www.postgresql.org/docs/current/libpq-exec.html)
- cancel request는 별도 connection으로 PID/secret을 보내며 성공 응답을 보장하지 않는다:
  [Canceling Requests](https://www.postgresql.org/docs/current/protocol-flow.html#PROTOCOL-FLOW-CANCELING-REQUESTS)
- database `CONNECT`/`TEMP`와 function/procedure `EXECUTE`의 `PUBLIC` 기본 권한을 role guard가
  고려해야 한다: [Privileges](https://www.postgresql.org/docs/current/ddl-priv.html)
- parser 후보의 source/dependency 성격은 각 공식 repository의 pinned source를 기준으로
  확인했다: [`pg_query_go`](https://github.com/pganalyze/pg_query_go),
  [`go-pgquery`](https://github.com/wasilibs/go-pgquery),
  [`pgparse`](https://github.com/zkrebbekx/pgparse)
