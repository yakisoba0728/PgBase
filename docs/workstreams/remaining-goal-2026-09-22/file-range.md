# Managed file byte ranges

PgBase managed file downloads support one RFC 9110 `bytes` range on authenticated, administrator, and public file-ID routes. Closed (`bytes=10-19`), open-ended (`bytes=10-`), and suffix (`bytes=-10`) forms return `206 Partial Content` with `Accept-Ranges: bytes`, `Content-Range`, and the selected `Content-Length`. A range beyond the object, a malformed range, or a comma-separated multi-range request returns `416 Range Not Satisfiable` and `Content-Range: bytes */<object-size>` after the normal file authorization decision.

`If-Range` is not exposed because managed file responses do not expose validators. A request containing `If-Range` receives the normal complete `200` representation. Go's registered GET patterns also accept HEAD: HEAD follows the same authorization and range selection, returns the GET status and exact headers, and writes no response body on the wire. Managed routes keep their existing `Content-Disposition: attachment` and `no-store` cache policy.

Local storage seeks and limits the open file. S3 issues a ranged `GetObject`; it does not download and discard the prefix. Transformed image responses sniff a bounded object prefix so newly generated PNG derivatives and legacy JPEG cache entries advertise their actual media type even when the selected range starts after the signature. Authorization, public-field policy, signed principal/file/variant token binding, object-key validation, transform policy, and download lifecycle hooks run before bytes are returned.

The range surface is capability-gated. Existing custom `ObjectStore` implementations that do not implement `ObjectRangeStore` keep the complete `200` response when a client sends `Range`, and PgBase does not advertise `Accept-Ranges` for them. A custom range-capable file service must explicitly report that capability. If an S3 object disappears between an invalid ranged `GetObject` and the bounded `HeadObject` used to obtain the current length, PgBase reports the same not-found result as an ordinary open rather than converting the storage race into a server error.

Regression coverage lives at the HTTP handler and native object-store seams. The handler tests status, range headers, closed/open/suffix forms, malformed and multiple ranges, and transformed MIME sniffing. Local storage tests byte-exact bounded reads; the MinIO integration test proves the S3 `GetObject` range metadata and bytes.
