### <a id="finding-authmail-001"></a>AUTHMAIL-001 · P2 · OAuth signup admits one empty-email account and rejects the next unrelated identity

상태: `confirmed`. 관련 기능: AUTH-14.

OAuth identity validation requires only a bounded Subject and allows an empty Email. In the unlinked registration branch, the service probes users by identity.Email and inserts the same value without requiring a verified non-empty address. PostgreSQL accepts the first empty string because email is NOT NULL and normalized, then the realm-scoped unique constraint and explicit existence probe make a second distinct OAuth subject with no email return ErrConflict. The pinned PocketBase flow deliberately supports an OAuth-created empty-email record and later fills it when a provider supplies an email, so this is not a required compatibility rejection.

근거:
