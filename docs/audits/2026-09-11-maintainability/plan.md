## 증거 상태와 한계

- PASS2 미도착 배치: 없음.
- final-risk-review: 완료된 표적 3차 판정을 통합했다. 새 정확한 실패 재현은 추가하지 않았으며 static defect/contract risk/maintenance를 구분한다.
- 각 도메인의 “2회 검토”는 coverage/report가 선언한 횟수다. coverage는 읽기·이해의 기계적 증명이 아니며, 기존 테스트 통과는 새 버그의 재현 증거가 아니다. 232개 기능표도 전체 무결함·완전 동등성을 증명하지 않는다.

Migration은 checksum 있는 과거 파일을 고치지 않는다. 데이터 의미 변경은 순방향 migration, 사전 점검, 백업·복구 검증을 포함한다. public API/SDK, exact text/ID, cursor/order, authorization, 데이터 보존은 각 PR의 명시적 비회귀 조건이다. LOC 목표·minification·주석만 삭제하는 방식은 금지하며, 아래 gross LOC는 보고서가 제시했을 때만 적고 나머지는 추정불가로 둔다.

## 주석·문서 정리 기준과 확인된 예

- 보존: schema의 advisory lock/fence generation·rollback/reconciliation·physical manifest ownership 이유, query/recordops의 policy-before-order·cursor wire 계약, self-update의 digest/probe/rollback 상태 주석, SDK exact JSON/CSRF 경계, UI의 불완전 숫자를 0으로 바꾸지 않는 주석, UI 지도 attribution/NOTICE, migration checksum·라이선스·생성 표식. 이는 구현 반복이 아니라 보안·동시성·데이터 보존·공개 계약 근거다.
- 삭제/이동의 확인된 예: `UI1-001`의 `ui/admin/handler.go:188` 중복 Referrer-Policy 설정은 하나로 통합한다. 문서 감사 항목 `DOCS-02-003`의 52개 generic observation과 `DOCS-07-P1-002`의 UI 재현 명령 분산은 현재 증거/재현 문서 한 곳으로 이동·중복 제거한다. `DOC8-P1-002`의 checkpoint narrative는 최종 verdict와 분리하고 역사 기록은 보존한다.
- 그 밖의 주석 삭제 대상·정확 LOC는 **추정불가**다. 각 PR에서 관련 수용 테스트로 계약을 고정한 뒤, 구현 반복/무효/작업일지만 삭제한다.
